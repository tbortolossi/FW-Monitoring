# ADR 0002: Split SNMP polling into fast and slow instances and harden runtime secrets

- Status: Accepted
- Date: 2026-09-22

## Context

Each firewall used one Telegraf `[[inputs.snmp]]` instance polled every 20 seconds. It walked about 93 PAN-OS global counters one by one, even though each is a scalar (`.0`), and also walked slow-moving tables (storage, host-resource devices, ENTITY sensors, Fortinet VDOMs and hardware sensors) at the same rate as CPU and sessions. This added avoidable SNMP work on the firewall management plane and made polls slower on large chassis.

Secrets had two weaker paths. SNMP discovery passed the community or SNMPv3 passphrases to `docker run ... snmpget` as command-line arguments, visible in `ps`, `docker inspect`, and audit logs. The generated Telegraf runtime env file used single-quoted values, which Docker Compose does not decode the same way: a doubled backslash is kept literally and a trailing backslash cannot be represented.

## Decision

- Render two `[[inputs.snmp]]` instances per firewall that share the agent, credentials, and tags:
  - fast, on the agent interval (20 s): system scalars, interfaces, processors, VSYS, zones, and the version-gated per-interface CPS and utilization tables;
  - slow, `interval = "60s"`: PAN-OS global counters, host-resource storage and devices, the opt-in PA-cluster table, and the chassis ENTITY tables (Fortinet: VDOMs, hardware sensors, HA members).
  Both use `max_repetitions = 25`. Measurement, field, and tag names stay unchanged because they are the dashboard contract.
- Fetch the global counters as top-level `[[inputs.snmp.field]]` entries, so Telegraf sends a few GET requests instead of one walk per counter. The slow instance is named `pan_global_counters`, which keeps those fields in that measurement; the `pan_system` scalars therefore stay in the fast instance.
- Gate `pan_interfaces_cps` on the inferred `panos_10_2_metrics` flag, and `pan_pa_cluster` on an operator-only `pa_cluster` flag (default `false`), because some PAN-OS releases stall `snmpd` on the cluster objects.
- For discovery, render a Net-SNMP client `snmp.conf` (`defVersion`, `defCommunity` or `defSecurityName`/`defAuth*`/`defPriv*`) and pipe it on stdin into the throwaway discovery container, which writes it to a private directory named by `SNMPCONFPATH`. Only the tool, host, and OID are command-line arguments. Values are quoted for `snmp.conf`; line breaks and NUL are rejected.
- Write `telegraf/paloalto-api.env` values in double quotes, prefixing each backslash, double quote, and dollar sign with a backslash; reject line breaks and NUL with an error that names the variable only. The collector's `--env-file` loader decodes the same format and still accepts the legacy single-quoted one. Encoder and decoder are a contract and are tested together.

## Consequences

- Load data (CPU, RAM, sessions, CPS, interfaces) keeps its 20-second resolution; counters, storage, sensors, and similar panels refresh once per minute.
- Upgrades see new or changed behavior: slower refresh of those panels, `pan_pa_cluster` only with `pa_cluster: true`, and `pan_interfaces_cps` only when PAN-OS 10.2+ is known.
- Rendering is plain Jinja2 with two blocks per firewall; templates grow a little, and tests assert the instance layout.
- Discovery credentials no longer appear in process listings or container metadata; the containers need `docker run -i`.
- Any secret value, including ones with `\`, `"`, `$`, `'`, or `#`, round-trips unchanged through Docker Compose into Telegraf. Existing runtime files are simply regenerated by the next `generate.py` run.
